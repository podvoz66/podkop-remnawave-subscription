# План и разрешённые границы

**PRODUCTION NO-GO.** До отдельного разрешения никаких установок/перезапусков/изменений VM202 или PVE.
Новый приоритет: [независимый rollback, Stage1/Stage2](../../docs/independent-rollback.ru.md).
Предыдущий rollback через новый guard недостаточен. Нужен изолированный OpenWrt-стенд,
проверенный LAN SSH PVE→VM и решение сценария SSH+guest scheduler unavailable.

Пользователь явно разрешил отдельную GitHub-ветку, разработку и локальные тесты.
Развёртывание VM202, перезапуски служб, cron/DNS/firewall/routes запрещены до
следующего согласования. Remnawave server templates/users/keys не меняются.

1. Сравнить установленный wrapper/.real.sh с main, сохранить manual links.
2. Подготовить isolated UCI candidate, штатный parser и real HTTP preflight.
3. Добавить независимый procd guard с DIRECT DNS, точечной очисткой Podkop,
   FakeIP blocker, lock/journal, cooldown и автоматическим recovery.
4. Проверить локально восемь отказных сценариев с реальными OpenWrt binaries,
   отделив mocks kernel/service boundaries от проверок HTTP/HTTPS.
5. Подготовить backup, rollout, rollback; опубликовать ветку/Draft PR без merge.

Критерий готовности разработки: тесты пройдены, diff не содержит конфигураций с
секретами, определены пределы совместимости и план контролируемого внедрения.
Критерий production-ready: отдельные LAN/SSH/LuCI/ZeroTier и reboot тесты после
разрешения; локальная suite не заменяет эту проверку.
